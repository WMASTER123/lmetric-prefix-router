冻结 worker 要求 TP2/DP1，启用主机状态缓存的调度器也要求 DP1。官方工具为每个服务申请设备锁及容器级互斥锁。部署者需要两个各获批两卡的隔离环境、可达的端点及平台支持的租约边界，或提供维护方支持的共存入口。仅更换端口或指定不同卡号不能消除该锁。双副本验收需记录双方同时在线和引擎回执。[安装器与资源准入](https://github.com/DeepLinkNext/DeepLinkEngine/tree/0ff0da7ad67e632a11f1ba6e5e08c8242bdfd6b8)

## r10 混合缓存口径

Qwen35 的 `LiveStateScheduler` 使用 `ResidentLeases.offer` 确定设备驻留命中。检查点要有真实保留的页，与请求缓存身份和 token 前缀一致，包括 MTP 前瞻 token，并且所有权、I/O 和写入完成状态满足准入。实际返回的可复用长度是游标。提示文本相同、单纯 FA 页命中、已有请求曾经在该副本完成，都不足以独立证明可复用。主机恢复是另一条路径，需按其实际动作与时延另行计量。当前可见的维护快照缺少完成栅栏、完整前缀身份和预留归属。收到正回执证明当次请求真实复用；下一次派发前需要有时效和代际的证据。

## 实验准入

1. 单 TP2 上采集冷、精确 token 续写、异 salt 和共享文档新问题的实际 cached_tokens。每次使用新 salt，缺少 usage 记为未知。重复测量独立记录。探针计时为整条非流式请求耗时。
2. 两端点同时就绪后，再做单热、双热、纯冷和重启干预，按目标端点核对派发前预测、可信覆盖率与独立实际回执。
3. 固定公开语料、到达轨迹、输出预算、种子及测量窗，轮换共同外部基线、纯最长前缀与 combined 变体。主场景为混合问答和突发，单热、双热和纯冷用于诊断。
4. 逐场景、逐种子报告 TTFT 分位数、达标数/测量窗、token 复用、已有请求 >200 ms 停顿、失败及代理在线开销。单副本直连结果单列。双端点无法同时在线或缺少可复核的派发前缓存证据时，停止比较和选型。

## 代码与制品

纯决策参照实验仓的冻结行为。独立连接池和请求计时从组织仓 Apache-2.0 的 `service/backend_pool.py` 和 `service/timing.py` 精简移植。开发网关在同一事件循环选点并记账，等待准入后检查证据代际，流式转发完成或异常退出后释放。单元测试用真实回环 HTTP 连接校验在途计数、转发、选点头隔离及失效证据不派发。真实宿主状态读取、服务健康成员管理和生产身份绑定仍需集成验证。
